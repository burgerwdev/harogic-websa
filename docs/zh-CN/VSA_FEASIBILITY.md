# SAN-90 上的 VSA 可行性(WebSA)

矢量信号分析(VSA)指既能*测量*数字调制信号、又能*解调*它:功率-时间、CCDF、
频谱与频谱图、星座图与 EVM;再往上一层要做符号判决与符号表。本文回答 WebSA
在 SAN-90 上能否提供这些、代价多大、以及绝不能假设什么。

这是一份分析:**当前不存在任何 VSA 生产代码**。文中每个数字都来自台面实测或离线
回环;原始证据在 [tools/vsa_probe/](../../tools/vsa_probe/README.md),完整结果表在
[tools/vsa_probe/FINDINGS.md](../../tools/vsa_probe/FINDINGS.md)。结论逐条标注
**[实测]**、**[推断]**(依据代码或 SDK 结构推理、未实测)或 **[未验证]**。

## 1. 结论

**分两层都可行,但有一个硬件约束和一个架构约束。**

* **[实测] Tier 1 便宜且低风险。** SAN-90 能完整捕获一帧 16 777 216 点(128 MB)
  的触发数据,零丢包、零短缺;Adaptive 连续流在 0.98–15.6 MSPS 下跑 40 秒零
  取数错误。功率-时间、对照 Rayleigh 的 CCDF、Welch 频谱、带软件载波恢复的星座
  图分别占实时的 3 %–316 %(只有频谱图和 Tier1 星座图超过实时,而它们本来只属于
  「先捕获再分析」模型)。
* **[实测] Tier 2 可行,但只能「先捕获再分析」。** 自研 NumPy 解调链达到匹配滤波
  理论界:25 dB 信噪比下实测 EVM 1.419 %、理论 1.406 %(QPSK);8–30 dB 范围内
  QPSK/16QAM 的 EVM/理论比都在 1.003–1.023。但该链对 16.9 ms 信号要花
  0.017–0.047 s(实时的 128–1176 %),因此必须跑在已捕获的帧上,而不是放进流式
  循环。
* **[实测] 厂商数字解调库这条路不通。** `Demod_Check() == -1`(没有
  `libDigitalSigDemod.so`,也没有许可),所以符号级的每一步都得自己写。下面的
  方案不假设该库存在。
* **[实测] 一个真实的硬件隐患。** 物理掉线后对已失效句柄调用 `Device_Close` 会在
  `libhtraapi` 内部**段错误**,worker 随即进入崩溃重启循环;设备不在总线上时
  `Device_Open` 返回 −1。这正是被推迟的「Web/SDK 进程分离」条目,§6 给出至少先做
  其中一部分的实测依据。
* **[实测] 绝对电平可信。** `RefLevel_dBm = 0` 时 IQ 通路在其线性区(约 −20 dBm
  及以下)与信号源电平相差 0.4 dB 以内,与厂商扫频迹线相差约 2 dB 以内。
* **[实测] 镜像不是问题;DC 频点存在一个与驱动电平相关的微小效应。** 所测各偏置下
  镜像抑制 78–92 dB,镜像不可能成为 EVM 的限制。而正落在 IQS 中心上的单音:−25 dBm
  驱动时比 ±500 Hz 处低 0.1–0.25 dB,−15 dBm(已压缩)驱动时低 1.0–1.6 dB,但同时
  的块*功率*在 DC 处不变——这是本振泄漏的相干矢量,不是陷波。因此高驱动下 VSA 不能
  把中心频点当作可信。

## 2. 能力边界

### 2.1 Tier 1 — 不做判决的矢量测量

频谱(Welch,绝对 dBm)、功率-时间与突发占空比、带 Rayleigh 参考的 CCDF、
频谱图/瀑布,以及由匹配滤波输出经软件定时与载波校正得到的星座点云。不做符号判决,
所以对任何信号都能用,包括调制方式未知的信号——这正是它作为安全第一层的理由。

### 2.2 Tier 2 — 自研 PSK/QAM 解调

符号率估计(盲估计或外部给定)、RRC 匹配滤波、定时恢复、载波恢复、PSK/QAM 判决、
EVM/SER 与符号表。因为 tinySA 只能产生 CW/AM/FM **[实测]**,该链在注入定时偏差、
载波偏差与 AWGN 的合成 QPSK/16QAM 上验证;它与理论噪声底一致,但**尚未**在真实
调制信号上验证——本台面没有校准过的 PSK/QAM 源 **[未验证]**。

### 2.3 明确不做

不实现 `SET_MODE 'vsa'`、不做前端面板、不写生产代码、不改动现有模式行为、不获取
厂商数字解调库、不实现 FT8/WSPR 等具体数字协议、不做硬件改造。这些属于*方案*,
不属于本次工作。

## 3. 实测证据 — 硬件

### 3.1 IQ 捕获:帧捕获与连续流

`probe_iq_capture.py`(SAN-90,tinySA 在 100.200 MHz 发 CW,−25 dBm)。

* **触发帧**(`FixedPoints`):连续 5 次各拿到 262 144 点、17 个包、0 错误、0 短缺;
  触发延迟 0.1 ms;33.5 ms 的信号在 34.7 ms 内取完(≈1.2 ms 固定开销)。同一次运行内,
  峰值落在指令 +200 kHz 偏置的 2 Hz 以内(200 002.0 Hz ± 0.47 Hz;另一次会话测得
  199 985.0 Hz ± 0.015 Hz,即信号源自身的设置重复性约 ±20 Hz);对 −25 dBm 源,峰值
  −24.48…−24.66 dBm(单次运行内 ±0.07 dB)。多包拼接干净:包边界的相位残差
  (最大 0.0098 rad)比帧内部(最大 0.0225 rad)还小。
* **可达深度**:在解调因子 4、16、64 下,2^14 … 2^24 点全部完整返回、0 错误。
  一帧 2^24 点在 dec 4/16/64 下分别对应 1.07 s / 4.30 s / 17.18 s 信号,取数耗时
  1.96 s / 5.05 s / 17.93 s。所以深度捕获可行,但**不比实时更快**。
* **触发语义**:`IQS_BusTriggerStart` 立即起帧(0.1 ms)。不调用它时,首次取数在
  配置的 `BusTimeout_ms` 之后返回 **−10(BusTimeOut)**(500 ms 配置实测 0.504 s)——
  可以当作「无信号」结果使用。
* **连续流**(`Adaptive`):40 秒 soak 在每种速率下都是 0 错误,最差 10 秒窗口速率比
  0.99848;而**重新配置后必须丢弃约 0.25 s 的排队数据**——不丢弃时切换解调因子会
  产生 10 824/10 824 次取数失败,丢弃后为 0。

### 3.2 电平、DC 与镜像

`probe_iq_level.py`。

* **绝对电平**:`RefLevel_dBm = 0` 时,源电平 −30 / −25 / −20 dBm 对应的 IQ 块均值
  分别为 −29.61 / −24.73 / −19.92 dBm(一次运行)与 −29.73 / −24.74 / −19.90 dBm
  (重复运行),即 **0.4 dB** 以内(重复运行的平均偏移 0.21 dB);相干单音估计与块均值
  相差 0.03–0.14 dB。
* **`ScaleToV` 在跨 RefLevel 时仍是绝对值**:RefLevel 从 0 改到 −30 dBm,
  `IQS_ScaleToV` 变化 33.7 倍 = 30.6 dB,与 30 dB 的设置变化吻合。因此
  `10·log10(mean|v|²/50) + 30` 配合厂商标定就是正确换算,不需要再补 3 dB 的
  带通因子。
* **余量随 RefLevel 变化**:`RefLevel = 0` 时线性到约 −20 dBm(−15 dBm 输入会低读
  3.9 dB);`RefLevel = −30 dBm` 时只线性到约 −25 dBm(−20 dBm 输入低读 6.2 dB)。
  压缩有两种表现——块均值偏低,且相干单音塌得更低——所以 VSA 必须按信号电平选择
  `RefLevel_dBm`,不能把它当作显示参考。
* **与厂商扫频迹线对照**:同一个单音走生产代码的扫频路径(`HarogicDevice` +
  `StdSession`),两者相差约 2 dB 以内;但这个对照受限于扫频迹线自身的峰值抖动
  ±2–4.6 dB。过程中踩到两个坑:200 kHz 跨度配默认最小扫频时间会得到**未标定**的
  迹线(不论源电平,峰值都钉在 ≈−19.5 dBm);`state.swp.*` 字段是平铺代理到
  `state` 上的,写错名字(例如用 `state.rbw` 而不是 `state.rbw_hz`)会静默保留
  100 kHz 的默认 RBW。
* **DC**:正好落在 IQS 中心上的单音,在 −25 dBm 驱动时比 ±500 Hz 处低 0.1–0.25 dB;
  在 −15 dBm(压缩工作点)驱动时低 1.0–1.6 dB。两种情况下 DC 处的块功率都不变,所以
  这是中心处的相干泄漏矢量,而不是陷波。±100 kHz 内的总跨度:−25 dBm 时 0.29 dB,
  −15 dBm 时 1.2–1.6 dB。
* **镜像**:两次运行在 100 kHz … 1.5 MHz 偏置下测得抑制 77.8–92.3 dB(QDC off,即生产
  默认)。镜像不会成为 EVM 的限制因素。

### 3.3 代价、丢包与恢复

* **[实测] 取数开销**:不带任何 DSP,只读取并拷贝 IQ 流,占单核的 1.5 %(dec 64)到
  18 %(dec 4)——DSP 预算从这里开始算。
* **[实测] 配置后丢弃**:0.25 s 的丢弃量就是「零错误」与「全失败」的分界(§3.1)。
* **[实测] 改解调因子可能把流卡死。** 三次 soak 里,六次速率切换中有两次让*每一次*取数
  在整个窗口内都返回 **−9(BusDataError)**(9622/9622 与 3608/3608);而同一速率在进程里
  单独跑时是干净的。生产代码的 `SdrSession` 已经把 `−9` 当作瞬态,并在持续出现时原地
  重配;VSA 会话必须复用这套恢复逻辑,而探针(没有恢复)正是发现该问题的途径。
* **[实测] 必须用生产代码的 `IQStream_TypeDef`。** `sdk_bindings` 按头文件把它重声明为
  正确的 728 字节——厂商封装里的副本少了 8 字节,SDK 在*每个*包上都会越界写入——
  所以任何新的捕获代码都要走 `sdk_bindings`,而不是 `htra_api` 的结构体。
* **[实测] 掉线即崩溃**:对已失效句柄调用 `Device_Close` 会在 `libhtraapi` 内部
  段错误(`web_sa/hardware/device.py:127`),worker 接着以状态 −11 退出并在设备缺席
  期间反复重启。Python 层抓不到它(见 §6)。
* **[未验证] 长期稳定性**:本次最长连续运行 40 秒;小时级行为、温漂、反复深捕获都
  没有刻画。
* **[未验证] `Bus` 以外的触发源**、超过 2^24 的 `TriggerLength`、连续背靠背帧,以及
  用于 VSA 捕获的 `DSP_DDC` 通路。

## 4. 实测证据 — 合成 DSP 回环

`probe_siggen_selfcheck.py` 与 `probe_dsp_loopback.py`,离线,无需硬件。

### 4.1 Tier 1 精度与开销

* **[实测] 突发占空比** 实测 0.500、期望 0.500。
* **[实测] CCDF**:纯噪声捕获相对 Rayleigh 参考的最大绝对偏差 0.0021(按单样本统计;
  块平均后的 CCDF 更陡,不能与该曲线比较)。
* **[实测] 符号率**:对 244.125 kSym/s 信号误差 −0.03 Hz(盲估计,来自 |x|² 谱线)。
* **[实测] 频谱法测载波**:功率加权质心在 10–40 dB 信噪比下**与信噪比无关地**偏
  −735…−778 Hz,跨噪声实现约有 640 Hz 抖动——这是有限数据导致的 PSD 不对称,不是
  噪声。它只能当粗指示,Tier 2 的估计器才是精确的那个。
* **[实测] 各测量占实时比**(33.7 ms 捕获):功率-时间 22 %,CCDF 3 %,Welch 频谱
  25 %,频谱图 120 %,Tier1 星座图 316 %。

### 4.2 Tier 2 的 EVM 与理论对比

参考界:匹配滤波理论 `EVM = 1/sqrt(sps · SNR)`,该式本身已在发生器自检中验证。

| 调制 | 8 dB | 12 dB | 16 dB | 20 dB | 25 dB | 30 dB |
|---|---|---|---|---|---|---|
| QPSK 实测 % | 9.986 | 6.314 | 3.991 | 2.521 | 1.419 | 0.799 |
| 16QAM 实测 % | 10.181 | 6.411 | 4.040 | 2.547 | 1.432 | 0.805 |
| 理论 % | 9.953 | 6.280 | 3.962 | 2.500 | 1.406 | 0.791 |

EVM/理论比 1.003–1.023,全程 SER 为 0。注入 0、0.25、0.5、0.75 个样本的定时偏差都能
恢复到 ≤0.03 样本(EVM 1.419 → 1.437 %);滚降 0.1 → 0.9 使 EVM 在 1.585 → 1.411 %
之间;载波估计在 1 % 符号率偏差下精确到 0.1 Hz。

### 4.3 退化与失败条件

* **[实测] 载波偏差**:EVM 1.419 %(0 Hz)→ 1.535 %(122 Hz)→ 2.846 %(488 Hz)→
  3.388 %(2441 Hz)→ 1.833 %(12.2 kHz)。非单调的形状来自粗估计残差与判决导向环
  需要吸收的量之差;要拿到最好的 EVM,真实 VSA 应把残差控制在符号率的 ~0.2 % 以内。
* **[实测] M 次方估计器自带四重相位模糊**:恢复出的星座可能整体旋转 0/90/180/270°。
  EVM 不受影响(最小二乘增益会把整体旋转吸收掉),但*符号表*会整象限错。产品化的
  VSA 需要已知前导/导频,或者只能把星座按「模旋转」呈现并交给用户旋转。
* **[实测] 盲符号率估计需要过采样**:每符号 2 个样本(符号率落在 Nyquist)时,|x|²
  谱线落到搜索带外,估计崩溃(1.95 MHz 符号率被报成 350 kHz)。该链需要
  **sps ≥ 4**,即 IQ 速率至少约为符号率的 3 倍。
* **[实测] 开销**:整条链(符号率估计、重采样、定时、匹配滤波、M 次方载波、
  判决导向 PLL、EVM)对 16.9 ms 信号花费 0.0177–0.0467 s——61 kSym/s 时是实时的
  128 %,244 kSym/s 时 546 %,977 kSym/s(每符号 8 样本)时 1176 %。逐符号的 Python
  循环式判决导向 PLL 是主要开销;把它向量化、或让环路以抽取后的速率更新,是最直接
  的优化方向 **[推断]**。
* **[实测] 构建过程中踩到的退化**(值得保留):必须丢掉匹配滤波的暂态与零尾巴
  (否则凭空多出 9.9 % EVM);判决前必须对符号做 RMS 归一化;假设的符号率一旦与真实
  值不符,重采样就会拉伸时基、使定时在帧内漂移(9.6 % EVM)。

## 5. 集成方案

### 5.1 模式与会话

在 `SET_MODE` 中加入 `'vsa'`,并在 `web_sa/measurements/` 下新增 `VsaSession`,沿用
现有 `MeasurementSession` 契约(enter/exit 带配置快照、`step()`、`health()`),
在 `web_sa/measurements/__init__.py` 与 `web_sa/web/commands.py` 的 `SET_MODE`
选项表中注册。模式私有状态遵循
[docs/zh-CN/MODE_STATE_FLOW.md](MODE_STATE_FLOW.md) 的约定:与
`SwpParams`/`RtaParams` 并列一个 `VsaParams`,重入时恢复,并由现有的
`SessionManager.switch()` 负责 `stop → exit → construct → enter → ready` 顺序。

### 5.2 采集模型

按操作分两条路:

* **先捕获再分析**(一切矢量操作默认走这条):按所需深度取一帧 `FixedPoints`,分析完
  再发布一个结果帧。实测深度到 2^24 点且零错误;取数大致是实时的,所以界面要显示
  进度,不能假装它实时。
* **流式 Tier 1**,用于频谱/瀑布/CCDF:用 `Adaptive` 流,配上和 SDR 会话同款的
  配置后丢弃,显示刷新 ≤30 Hz。实测不带 DSP 的持续开销是单核的 1.5–18 %,还够跑
  Welch 频谱(实测 25 %),但不够跑频谱图(120 %)。

窄带信号可以用 `DSP_DDC` 通道收窄分析带宽(复用 `web_sa/demod/ddc.py`),但该通路
尚未按 VSA 配置实测 **[未验证]**。

### 5.3 帧协议与前端

* 频谱/瀑布视图**原样复用 RTAF**:它已经在 RTA 画布上渲染,SDR 模式也验证了这个
  模式。
* 为矢量数据新增一帧——`VSAD`,载荷包含符号点云(float32 交错 I/Q)、参考/理想点,
  以及一份紧凑的测量字典(EVM、MER、载波偏差、符号率、定时、信噪比估计)。沿用
  `web_sa/measurements/framer.py` 现有的 16 字节头框架,并在
  `web_sa/web/client_stream.py` 的 latest-wins 策略中登记(星座图是快照,
  latest-wins 正合适)。
* 前端:频谱/功率-时间/CCDF/频谱图复用 RTA 画布,另加星座面板与 VSA 设置组。
  `SET_MODE` 处理、模式私有设置恢复、画布交互在 RTA/SDR 上已经存在,不需要新的
  渲染引擎 **[推断]**。

### 5.4 配置项与能力极限

对外提供:中心/跨度(或中心 + 捕获带宽)、捕获深度或时长、`RefLevel_dBm`(文档要写明
它就是*输入增益*,并给出实测余量)、解调因子、Tier1 视图选择;Tier 2 另加调制方式、
符号率(或盲估计)、滚降,以及是否用前导解决相位模糊。所有极限必须来自
`DeviceCapabilities`/`HardWareState` 与 `IQS_StreamInfo`(采样率、带宽、包大小),
不得写死:仓库本来就有设备极限的单一来源,而本文测到的深度是探针的选择、不是设备上限。

## 6. 进程模型 — Web/SDK 分离

架构评审把「Web 与 SDK 常驻进程分离」推迟到 VSA 阶段,`KNOWN_ISSUES.md` 也重复了
这一点。现在这些实测给了这次推迟一个具体的代价:

* **[实测]** 已失效的 SDK 句柄会让 `Device_Close` 在 `libhtraapi` *内部*段错误。
  Python 抓不到,整个 worker 直接死掉(退出码 −11),supervisor 在设备缺席期间反复
  重启。对 VSA 而言这比频谱显示更糟:一次深捕获握着数百 MB 缓冲和很长的 DSP 结果,
  全都会丢。
* **[实测]** 恢复的前提还有一条:链路一旦确认失效,就根本不该再调用
  `Device_Close`;而现在的 `reopen()` 会先调 `close()`。

建议按「最小可用」的顺序推进:

1. **现在就能做(便宜,不新增进程)**:让 `reopen()` 在链路已标记失效时跳过
   `Device_Close`,并把 `Device_Open` 失败当作可重试状态而不是崩溃路径。这能消除
   实测到的崩溃循环。
2. **VSA 阶段**:保持 supervisor/worker 形态,但把*SDK 会话*(打开/配置/取数)挪进
   一个专用子进程,worker 通过管道与它通信,这样原生崩溃的代价是一次 IQ 捕获,而不是
   整个 Web worker。分析仍留在 worker 里,因为 NumPy 缓冲本来就在那里。
3. **更晚**:彻底分离(一个 SDK 守护进程独占设备,Web worker 退化为客户端)——只有
   当设备出现第二个消费者时才值得。

第 1 步已实现并台面验证(**随 v1.7.4 发布**:设备不可用时不再产生 core、安静重试、
设备释放后自动恢复、两种链路状态下停机都干净;supervisor 也在连续 5 次「启动后 10 秒内崩溃」
后停止)。第 2、3 步仍待做。

对现有恢复链路的影响:第 1–2 步不改变 RTA/SDR 的会话重配置、链路看门狗或模式切换;
它们改变的是*SDK 调用发生在哪里*、以及崩溃时会发生什么。第 3 步会触及 supervisor
契约,应作为独立的改动。

## 8. 风险与阻塞项

* **[实测]** 厂商库在恢复路径上的不稳定(§3.3、§6)——这是*常驻* VSA 唯一的实测
  阻塞项。
* **[实测]** 一次 IQS 重配可能把流永久卡在 `−9`(多速率 soak 中 6 次切换有 2 次);
  恢复逻辑必须从 SDR 会话复用,不能另起炉灶。
* **[实测]** 流式 Tier 2 在 NumPy 下是实时的 5–12 倍;设计必须走先捕获再分析,或者
  把 PLL 向量化。
* **[实测]** 盲符号率估计在接近 Nyquist 时失效(需要 sps ≥ 4)。
* **[实测]** 没有前导时存在四重载波相位模糊。
* **[实测]** 精度受本台面信号源限制:tinySA 没有可溯源的绝对标定,所以「0.4 dB 以内」
  指的是通路一致性,不是实验室精度。
* **[实测]** 中心频点的行为随驱动电平变化(§3.2):把 DC 区域平均进测量的 VSA 会看到
  0.2–1.6 dB 的相干泄漏。
* **[未验证]** 长期稳定性、`Bus` 以外的触发源、基于 `DSP_DDC` 的 VSA 捕获,以及
  Tier 2 在*真实*调制信号上的表现(本台面没有 PSK/QAM 源)。
* **[风险]** `RefLevel_dBm` 兼任输入增益:如果 VSA 把它当作显示参考暴露出去,强信号
  会被静默压缩(已实测,§3.2)。
