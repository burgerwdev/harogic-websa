# 架构

采集快照将 `state:running|idle|failed` 与设备连接状态分开；`parameters_state:live|last_known|unknown` 分别表示当前源参数、保留的上次参数及源尚未打开。未知时带宽／输入率为 null，`center_hz` 仅为请求中心，epoch `"0"` 为哨兵，不表示活动流；独立基带夹具标记 `parameters_state:simulated`，共享显示窗口／率为模拟值，epoch `"0"` 为哨兵，真实基带输入以各路 clock 为准；硬件已知时输入率取 PFB 输入率，epoch 为 DSP 源代次，不能混用设备配置代次或下游 DDC 率。失败／停止保留原参数，重开源分配新 DSP epoch。启用硬件信道的变更须有健康活动采集。旧服务可能缺少 `parameters_state`，失败后仍报告旧版缺省值。

主面板输入中心频率后，将共享采集中心和 C1 监听频率一起设置到该点；已有放大框保持宽度并平滑滑到该点。IQ 带宽只修改采集带宽，保留逐路频率与模式；“移到中心”将采集移到 C1 当前频点。主面板其他调谐／解调／共享 PCM 参数仍作用于 C1；多路操作在工作台选中并编辑各 UID。采集变更可能中断所有信道并产生录制边界。


`recording_audio_read.rs` 在 `recording_audio.rs` 的完整流式日志校验器之上生成有界原始PCM快照，仅保留所选样本帧及原时钟条目，复用原Float32 WAV头，不分配实时槽或DSP生产者。成功前校验完整任务；当前无音频定位索引，准备耗时随任务长度增长，所选PCM／时间线／清单各有内存上限。不可变快照共用读取／producer／body名额及传输预算。按需加载的 `recordingAudioView.ts` 拥有单个原生媒体播放器、精确十进制选区、有界响应组装、同份快照下载及编辑／隐藏／替换时的取消释放。播放器时间相对选区，原AUD2时钟及整数裁切偏移另行保存。见[API](API.md)。

文件频偏调谐按 `iq_file_demodulate_offset` 能力开放。`recording_demod.rs` 在原模拟 IF 滤波及重采样前复用 `ddc::Nco::mix_exact`，局部 f64 scratch 同样限定为8192样本。新增精确入口处理微小非零频偏，现有实时调用保留原近零旁路；NCO 状态跨校验访问器的块／卷回调保持。准入校验平移后两个边带端点与已录频带及实际Nyquist。派生调谐仅写入解调清单，原SigMF频率与精确时钟不变。

`recording_demod.rs` 通过共享原生模拟解调核，对已结束 IQ 范围执行有界 AM／USB／LSB／NFM 文件处理，包含实际 IF FIR 与重采样。在采集锁外遍历已校验 v2 块，原精确时钟与范围相对播放时间分开，不将退役 UID 接到实时槽。成功前完整生成并验证派生结果，然后经共同单读名额及有界管道输出不可变 Float32 WAV／来源 tar。PCM、来源及清单均有上限，不增加 codec 依赖或实时生产者。`recordingDemod.ts` 拥有唯一有界文件播放器，范围改变、隐藏或销毁时取消请求并释放旧媒体。滤波、时间及大小限制见 [API](API.md)；数字文件解码继续单列。

`recording_flac.rs` 在已校验的发布音频读取器之上增加离线下载转换。固定比例量化为 signed-24 PCM，保存削顶统计，各片段按真实率／声道输出 FLAC；原 Float32 日志／WAV 保持逐位一致。`flacenc` 0.5.1 关闭并行特性，只保留一个4096样本编码块和一个校验日志条目。预检无临时文件地计算 STREAMINFO／MD5、长度和摘要，流式输出再次验证；清单与片段计划共限2 MiB。FLAC 与 IQ／WAV／结果复用单读名额及传输预算，不占实时处理 worker 或硬件槽。转换及完整性语义见 [API](API.md)。

`recording_audio.rs` 拥有实际发布 Float32 PCM 的持久轨道，复用 `recording_journal.rs` 的有界 CRC／Zstd codec。实际包配置随音频贯穿 worker、排空与退休路径，排队 PCM 不套用较新的可变设置。音频、IQ、结果共用三个录制 worker；恢复保留原身份及校验前缀，WAV／逐帧时钟下载复用既有单读名额与有界传输。浏览器增益／声像／静音／Solo 不进入样本，后端共享处理保留。协议输入音频、Opus 与数字文件解码仍待后续，详见 [API](API.md)。

`recording_results.rs` 将持久结果轨道接入共同的录制管理器。`service_stream::deliver_receiver` 在订阅者快照／序号改写前只观察一次原始 SDE2，`multichannel.rs` 映射其原处理流、基带和 UID。结果与 IQ 独立任务共享三个 worker、4 MiB／64 项／2 秒限额。WBRS0001 对每条有界 JSON 和每卷尾部分别压缩／校验；图像保留准确增量像素，不从浏览器或另一个解码器生成文件。安静的结果源可持续等待，明确处理退役／失败在旧尾发布后封闭接入。恢复与 tar／JSONL 下载保留原服务、UID、处理时钟及部分图像语义，下载复用 IQ 的 producer／body 名额与有界传输。协议输入音频、Opus 和数字文件解码仍待后续工作。

`recording_collection.rs` 将已结束任务的独立源片段打包为 SigMF 集合，复用 `recording_export.rs` 的校验成员／元数据写入及预检、producer、body 共同持有的单读名额。成功响应前预检全部片段，各自保留样本编号、真实率、频率和精确来源；有序集合引用生成的元数据文件基名及 SHA-512。样本和注释不累积，只保留有界片段计划及集合清单（各至多 2 MiB、至多 4096 片段、合计至多 1,073,741,823 样本）。全部成员输出校验后才输出集合清单，不借硬件槽重绑旧 UID。

后端 IQ 记录由 `recording.rs` 拥有。现有 `tag_iq` 发布边界将同一不可变 Bytes 接入记录和网络；记录是独立消费者，浏览器退出不结束接入。最多三个活动 worker，每任务 4 MiB/64 项/2 秒预算包含在途块。IQ、音频及结果 worker 最多合并32项／约1 MiB，合批等待至多50毫秒；先同步数据及存在时的IQ旁路索引，再同步清单并发布计数。整批在途输入仍占用原队列字节／项数／最旧年龄预算，块编码及源边界保持。压缩、校验、索引、fsync 与恢复不持有采集状态锁。停止先封闭接入再排空，错误仅使对应任务失败。服务启动时恢复历史并标记中断任务，旧 UID/服务身份不重绑。正式 WBIQ0002 采用 Zstd level 1、原始块回退、CRC32、有界索引页和分卷；实验 WBIQ0001 保留。已结束任务由 `recording_read.rs` 复用 v2 校验定位读取，单个阻塞 worker，每范围限 8 MiB CF32／4096 块／4 MiB 来源元数据。`recordingView.ts` 为页面拥有一个波形缓冲，支持样本定位、实际率波形回放和解压后 SigMF 下载，与实时采集独立。协议输入音频及数字文件解码仍待后续切片。

大范围 SigMF 导出由 `recording_export.rs` 和共享 v2 `visit_range` 逐块访问器实现。准备阶段计算精确 tar／元数据长度及校验摘要，不累计样本或注释；数据和元数据输出阶段重新校验，文件变化会使响应在宣告长度之前中断。只保留一个裸块、一项有长度上限的索引／注释及两项 64 KiB 传输，与所选长度无关；读取准入与 `/range` 共享。取消必须返回终止性的写入错误：`Write::write_all` 会重试 `Interrupted`，用它表达 HTTP 消费者取消会空转并占住名额。响应／生产者共同持有名额与取消标记，双方释放后回收。浏览器交给原生下载处理，波形内存仍限 8 MiB。

工作台的主要操作区保留控件、数值和真实状态。监听音量／声像即时显示数值，未监听／停用／故障时禁用，并显示总静音／独听屏蔽；浏览器报告单声道设备时禁用声像。它们只控制本浏览器扬声器，独立于共享 PCM 和文件。来源／格式细节放在折叠区或悬停提示。

单信道预设由 `backend/src/bin/websad/receiver_presets.rs` 持久保存于实例独占目录；独立互斥锁在采集锁外完成磁盘操作。只保存已确认的频点、基带和处理参数。`frontend/src/ui/receiverPresets.ts` 在稳定DOM子树中提供保存／预览；载入复用现有接收器预检与提交，保留目标身份和启停，预览修订过期时拒绝提交。预设不是自动恢复的接收集合或多路原子场景。

`receiverModeMemory.ts` 观察会话的已确认快照，按 UID／模式记忆 IQ 要求、解调带宽和共享音频参数。有界且校验的浏览器标签页存储可跨本标签页刷新，清理已删除 UID，并在服务变化时重置；不含频率、身份、接收启停、监听路由或任务。切换模式只恢复表单候选，仍需准入和显式提交。后续表单 input／change 会移除旧应用预览，防止提交与当前表单不同的候选。

## 系统与所有权

原生 Rust 服务负责设备配置、采集、信道化和接收 DSP。C++ shim 串行调用 HAROGIC 官方 SDK。浏览器负责控制、频谱绘制、解码结果展示和音频播放。`tools/reference/` 中的 Python 模块仅供离线数值参考和 fixture 工具使用。

```text
浏览器控制 → HTTP/WS 命令 → 原生模式所有者 → 保留的 SDK session
SDK IQ + FFT → 有界采集队列 ┬→ 有序 PFB workers → fine DDC ┐
                           └→ 原始 IQ 直接 DDC ───────────┤
                                                         └→ 成帧 → IQBF/IQAX 消费者
                                                                  └→ receiver workers → AUD2/SDE2 → 浏览器
SDK SWP/RTA 迹线 → 显示发布器 → 浏览器频谱/密度/瀑布
```

SWP、RTA、SDR、谐波和相噪各自保存配置，共享一个物理设备 session。STATUS 发布设备实际值和能力。命令校验及候选计划准入在替换活动状态前完成；拒绝请求保留原计划和原流。

`multichannel.rs` 将稳定逻辑 UID 私下映射到兼容槽；公开集合面向动态路数，当前限制三个定义。独立基带要求经 `RatePlan::baseband` 规划，空处理器集合绕过接收 worker。按 UID 的 IQ 网络输出共享编码字节，各订阅有独立有界队列。所有工作台窗口共享浏览器适配器与会话，窗口生命周期不启停接收。见 [P3 契约](MULTICHANNEL_DRAFT.md)。

P4 的处理流与独立 IQ 分别拥有身份。`multichannel.rs` 保留处理流到原 IQ/UID 的映射，
`service_ddc.rs` 比较实际采样计划，处理分支变更不重建相同基带；worker 的起始使用实际首块源位置。
音频/解码队列仍按源身份准入，发送时保留处理身份及原 UID，退役尾部不会污染复用槽。
`nativeWorkbenchStreams.ts` 为所有窗口共享 UID 结果与本地音频消费；`sdrAudio.ts` 复用既有时钟适配和 worklet，
在浏览器 GainNode/声像/主输出执行本地混音。旧后端 volume 仍属于共享 PCM 增益。详情见 [P4 契约](MULTICHANNEL_DRAFT.md)。

工作台按稳定键原位更新节点，轮询保留聚焦控件、草稿、展开状态和滚动容器；指针释放仍绑定 Pop out/Dock 后的当前所属文档。
`receiverDecodeView.ts` 只拥有此视图的筛选、UTC、排序、分页、图像选择和清空可见历史状态。
“清空视图”隐藏此视图已有消息/图像、保留实时状态，不发送接收或记录命令。
`decoderResults.ts` 复用实时表格分页、原生画布及已加载 PNG 条带。
原生遥测按事件类型分别保留快照，避免 NR 状态覆盖 AM/WFM/解码器读数。

工作台从唯一模式选择派生内部处理用途；扬声器路由、IQ 录制和输出订阅继续独立。
`workbenchTips.ts` 提供操作提示；`audioScope.ts` 与旧 Decode 共用真实音频绘制，不依赖旧全局状态。
`receiverExport.ts` 下载筛选后的保留消息快照和选中 PNG，保留结果／源归属及时间语义，
不创建接收／录制生产者，也不增加后端录制种类；PNG 导出另有 20 MiB RGBA 限额。

## 设备 session 与采集

一个长期运行的 SDK 管理线程负责 SWP/RTA/IQS/PNM，所有 SDK 调用均串行执行。设备正常时，采集模式之间的切换只停止采集并释放模式状态，保留物理句柄。`Device_Open` 使用长期会话中地址稳定的 `void**` 句柄槽：厂商 PNM worker 会保留该地址，直到物理连接关闭。失效或断链句柄不得传给 `Device_Close`。

IQS 配置与启动采集（arm）分开。服务先准备 PFB、fine DDC、接收器工作线程和元数据，再显式启动采集；恢复时也遵循此顺序。首包予以保留，并校验包序和硬件时间戳。主机样本索引不能替代对硬件连续性的核对。

IQS 返回 `-12` 时，若包含有效 IQ 包，服务保留样本及时间戳，通过 `status_warning=-12` 单独报告饱和。未显式启动 Auto 时，饱和保持手动 Ref，也不会把有效包计为总线失败。显式 Auto 恢复有明确上限，且只使用同一模式、同一配置下的新观测，详见 [MODE_STATE_FLOW](MODE_STATE_FLOW.md)。IQ、FFT、告警和计时经同一次 `san90_next_v3` 返回；例行元数据轮询不消费 IQ。畸形包和真实时间戳断裂显式失败。

SDK 持续停滞时，以原始原因结束采集。恢复须创建新的采集 epoch，不能续接旧硬件时间戳。队列积压时按有界背压等待，直到明确失败，不重新打开设备。厂商管理线程卡在 SDK 调用中时，保留该线程，拒绝调用 SDK finish 或重新打开设备。

定期获取 GNSS 状态时使用 SDK 缓存快照。设备和可选时钟能力根据成功打开设备及读取硬件状态的结果确定；缺失数据保持未知。外部参考配置为 10 MHz。恢复时显式将物理会话标记为失效；退出时先结束模式管理逻辑，再关闭会话并等待 SDK 线程结束。

Server 是独占交接。进入时停止并结束 Web 采集及接收工作，再由 `san90_session_release_v1` 关闭空闲物理句柄，保留可复用的 SDK 管理线程。缺少释放 ABI 或厂商管理线程仍停在 SDK 调用中时拒绝交接；已经结束的流保持结束，恢复时创建新 epoch。`backend/src/bin/websad/server_mode.rs` 管理 SoapySDRServer 子进程、依赖探测、有界原始日志和生命周期状态。专用的启动线程保持运行，直到该子进程被回收，并启用父进程退出清理。退出 Server 必须先停止并回收子进程，Web 采集才能重新打开设备。进程生命周期不由浏览器控制。Server 发布 `connected=false`、`gnss=null` 和空的活动实际值，不轮询 SDK，也不共享 Web IQ。SoapyRemote 客户端通过打过补丁的官方 SoapyHarogic 模块打开设备；监听就绪本身不能证明设备已打开或已接收 RF。

SoapyRemote 在 setup 阶段就启动读取线程。官方驱动的兼容补丁因此在激活前即返回稳定、非零的 16384 样本 MTU，并让未激活/已停用的读取遵循调用方超时；否则会出现零样本传输或客户端收到 `STREAM_ERROR` 后停止接收。该传输分块上限与 SDK 包长相互独立。

驱动按 SDK 的原始 CS8/CS16/CS32 宽度保存样本，实际输出请求的 CF32/CS16/CS8，整数格式匹配时批量复制。SDK 宽度在 setup 时选择，关闭流前保持不变；CF32 按源宽度归一化。setup 前，原生格式查询默认在不超过 60 MSps 时返回 CS16（`fullScale` 为 32768），高于该速率时返回 CS8（`fullScale` 为 128）。setup 后返回所选输出格式及其 `fullScale`（CF32：1、CS16：32768、CS8：128）。`native_format=AUTO` 对整数输出采用相同宽度；对 CF32 按 setup 时的采样率选择，不超过 60 MSps 使用 CS16，否则使用 CS8。显式指定 SDK 宽度时，整数输出必须与其匹配。USB 枚举使用 `Device_List`，不打开设备。构造函数打开一个支持采集的句柄，用于身份、能力查询及后续流；停用与关闭流保留该句柄，设备对象销毁时释放。主机队列约容纳 50 毫秒 IQ，至少容纳两个 SDK 包及 16384 个样本，并复用已分配存储。活动读取返回不超过请求数量的已有样本。设置未变时跳过 SDK 重配。OnAir 切换模式或采样率时可能销毁并重建设备对象，因此仍需一次物理 SDK 打开。见[工具指南](../../tools/README.md#soapy-server-driver-setup)。

### 粗 PFB 与 fine DDC

全带宽采集输入为 62.5 MSps，可用带宽为 50 MHz。共享二倍过采样 PFB 使用 128 个频率箱，步长为 64 个样本：粗频率箱间距为 488.28125 kHz，每箱输出采样率为 976.5625 kSps。窄带设备采集会相应调整这些参数。频率箱数量、间距和输出采样率是不同的量，均不代表产品提供的接收器数量。

原型滤波器支持每相 4、8 或 16 个抽头，服务默认使用 16 个。通带和混叠抑制取决于抽头数及频偏。粗通道路由的 fine 计划必须落在所选频率箱的可用通带内，不能截断宽带信号后仍视为等价接收。描述符要求的最低 IQ 速率超过粗通道速率时，使用共享原始采集的直接分支，独立执行频移与多级抗混叠抽取；其占用带宽和过渡带必须落在可用采集带宽内，不拼接相邻 PFB 箱。

每路接收器独立保存频率、模式、占用带宽、`RatePlan`、振荡器相位、滤波历史和输出率。fine DDC 频移后执行多级抗混叠抽取，必要时在接收器输入适配精确协议率。播放采样率不是所有模式的 IQ 率下限。USB/LSB 包络覆盖边带上限，CW 包含 pitch，FT8 至少保留正频率 3.2 kHz，SSTV 至少保留正频率 3 kHz。界面为 DRM 选择 12 kHz 接收窗，直接 API 请求可使用其他通过准入的值；显示的窗口随 `±confirmed_ifbw/2` 变化，不随 FAC 占用带宽改变，因此不表示自动接收全部 4.5~20 kHz。DRM+ 界面使用固定 100 kHz 频道，这不表示最外侧 OFDM 载波恰好位于 ±50 kHz。

两种路由均发布整数抽取后的实际频道时钟 `source_rate / decimate`，即使它不同于解码器要求的精确速率。接收器的 `Rational` 适配器转换到协议输入率，包括描述符要求的 4 MSps 或 2 MSps；成帧和注册表始终保留真实频道率，修改报头不等于重采样。

GPS 在速率适配前要求至少 2.6 MSps，GNSS-SDR FIFO 输入则保持精确 4 MSps。2.046 MHz 占用带宽加上两侧各 255.75 kHz 的过渡带，需要 2.5575 MHz 的采样带宽。因此，信号位于中心时，3.90625 MSps 采集可保留所配置的波形，再插值到 4 MSps；采集边缘准入仍计入完整滤波包络和调谐频偏。

有理采样率适配器预先计算时钟增量，并为约分后的小比例缓存最多 256 个精确分数相位选择项，包括 GPS 的 128/125 转换。更大的比例仍使用有界的插值滤波网格。缓存只减少相位选择计算，不改变滤波系数、样本数或源时钟精度。

没有活动采集时，频道准入按已配置的采集中心和显示宽度规划候选接收器；状态中的回退带宽不代表实测或协商后的源速率。

fine 频道末级 FIR 按请求的射频过渡带设计，与所选输出采样率分开。解码器采样率下限和整数抽取档位不会扩宽该滤波器。WFM 保留立体声/RDS 所需的处理采样率，但窄射频滤波器可能移除这些分量。射频带宽与 WFM 固定 15 kHz 的节目音频低通不同。

主频道调谐超出采集范围时，先验证所有已开启频道，再移动共享采集中心。辅助频道不能独立移动中心。拒绝配置保留所有活动频道。在当前计划内可完成的变更尽量只更新目标 fine 接收器。

### Workers、准入与背压

原始采集队列容纳 64 包。PFB 使用四个固定 worker，最多六个任务在途，按输入顺序收集结果。fine/成帧交接容量为二。两个固定 receiver worker 独占频道可变 DSP 状态；另一个 FT8 worker 执行搜索，避免阻塞实时监听。DFN 模板在采集前准备，各接收器独占可变处理状态。

基带生产端和 worker 每块最多接受 65536 个复数样本。成帧器按此上限拆分不等长输入包，保留每个样本及各帧首样本的因果采集位置，应用固定 1/32768 ADC 归一化，finish 时以连续序号输出剩余尾部。IQ 必须为有限值，`input_index` 不能为 `u64::MAX`，源采样率必须在 1..1e9 Sps 内。停止或失败时，receiver worker 对每项排队工作只释放一次待处理计数。主路停用后，重新采集或停止时仍保留已启用辅路的尾帧；成帧器 finish 只处理已启用频道。

后端保留三个兼容槽，原生信道工作台以动态 UID 集合管理当前三个定义。进入 SDR 不再隐式停用辅助槽。工作台提供本地多路混音及按 UID 的音频/结果消费；后端提供持久 IQ、结果及实际发布音频记录。粗频率箱数量及内部基准路数不代表产品容量。

三个槽位共享一个 RF 采集窗口。每个已启用槽位根据模式描述符的最低输入率选择粗 PFB 路由或原始 IQ 直接路由；两者可在同一采集内共存，但槽位预算不能相加成更宽的接收器。提交变更前，采集范围须容纳每槽的占用带宽和过渡带。

准入在更改采集、身份或注册表前检查频道数、合计输出率和 DDC/成帧成本。校准在采集前测量所选粗通道或直接原始输入内核及成帧周期，并在进程内复用。直接路由按每原始样本成本乘完整采集率计费，粗通道路由按每粗样本成本乘粗通道率计费，保留二倍余量：`2 × sum(每源样本成本 × 源采样率) <= 1e9 ns/s`。这是内部保守 CPU 预算，不证明 SDK、PFB、接收器、网络或录制容量，也不表示宽带实机接收或 RF 互操作已经验收。

显示帧可用新帧替换慢客户端的旧帧。原始 IQ 和频谱处理使用有界队列背压，直到明确失败。有序 IQ、PCM 和解码输出在队列溢出时报错，不丢弃样本。音频容量反馈计入排队和未确认的 PCM。解码批次大小有上限，按 FIFO 顺序应用后确认。启用 ACK 的解码 socket 最多允许 16 个事件且不超过 4 MiB 线路数据等待确认，按 `(channel, channel_id, epoch)` 累计确认，最早尚未确认的事件保留 5 秒期限，批次与快照发送期间也受其约束。已接纳的接收器音频与解码事件（包括初始快照）在重调及采集 epoch 切换后仍保留，先按 FIFO 到达订阅者，再交付退役尾帧和新的接收器身份。解码队列退役保留未受影响的频道。采集 epoch 边界仍用于原始 IQ、显示数据和新数据包的接纳。协议和反馈契约见 [API](API.md)。

共享 receiver worker 故障会停止所有接收器的音频与解码处理。服务保留诊断及 worker 计数器，停止接收 worker，并关闭 PCM/事件订阅；采集、粗 PFB、fine DDC、原始 IQ、频谱和瀑布继续运行。`sdr.receiver_error` 保存故障，专用 `RECEIVER_ERROR` 事件携带 `{error, failed:true, scope:'all_receivers'}`。接收器故障不写入全局 `last_error` 或 `ddc_error`，也不在频谱上显示错误遮罩。采集和设备故障仍走全局故障处理路径。

调谐与缩放仍可使用。显式选择 `mode` 或 `demod` 可请求恢复，重复选择当前模式也可重试。恢复前须等待停止的工作线程退出，并关闭失败订阅。此前的请求返回 `receiver_retiring`，须稍后重试，不会安排自动重启。为恢复尝试创建的工作线程在尝试失败时一并停止，因此故障锁存总是意味着工作线程正在退出，后续重试能够完成清理。替代线程数量有上限。恢复使用新的流身份和起始边界，不拼接缺失区间两侧的 IQ。正常重配置按顺序发布旧流尾帧；接收器故障时无法保证尾帧完整。音频和解码控件就地显示错误，硬件连接状态不受影响。

SDC 提供复用配置前，DRM30 最多保留 13 帧完整等化帧，DRM+ 最多保留 16 帧，满足长交织器预热和超帧对齐需要。保留的帧包含原有 FAC 标记和源样本位置。选定模式的定时路径按绝对样本坐标裁剪未同步 IQ 历史。这些历史容量限制不丢弃输入帧，也不改变流身份。已有配置下的解码不变；失锁恢复会清除解码状态。

DRM 拒绝长度不足的畸形 SDC 实体，即使其 CRC 正确。失锁恢复重新搜索鲁棒模式，并清除旧电台与解码器状态。MSC 间断清除交织器和音频残留；xHE CRC 失败会计数，但不交付失败数据。FAC 指示的短交织生效。完整的信令重配置及下一复用配置的生效时序仍不支持。

### 流身份与时钟

IQBF/IQAX v2 使用 `(epoch, channel_id)` 标识流。重调更换频道身份，新 DSP/采集计划更换 epoch。旧输出先于新流空 `seq=0` 边界结束。拒绝请求不分配新身份。注册表和频道时钟来自同一不可变流水线快照；退出 SDR 后清空。

IQ `input_index` 是首个输出在采集复数样本域中的因果位置，不是包首。群延迟独立传输，单位为输出复数样本。对齐公式为 `input_index / input_rate - group_delay_samples / output_rate`。合帧保留首段非空输出时钟。消费者必须精确保留 u64 索引。

AUD2 携带交错 f32 PCM、实际率和声道、流身份、PCM `audio_index`、采集输入位置及分数时刻。SDE2 携带相同身份和时钟语义的解码事件。总延迟未知和因果播放有明确标志，两者均不允许宣称精确源对齐。解码窗格通过模式标题的工具提示展示这些时钟详情，而非常规显示标题栏标签。DRM/DRM+ 的时序与电台锁定和音频播放状态无关；解码器错误仍显示在标题栏。FT8 结果保留原搜索窗口时刻。新订阅者获得自己的起始边界；晚订阅 SSTV/无线电传真获得有界当前图像快照，不重置接收器。完整布局及排序见 [API](API.md)。

浏览器按流身份和 transmission ID 将存储段归为逻辑页；接收器重置、换频、换模或断线均保留图像，收到行后才建立历史记录。每频道 Gray8 实际分配预算为 20 MiB。当前页和正在查看的页受保护，其他页按最旧优先淘汰；淘汰数量和留存受阻状态均可见。删除接收中的页后，该 transmission 的后续行不再保存。显式清空和 Preset 可以删除图像。历史仅在当前浏览器会话内保留，晚订阅只能恢复后端有界的当前页快照。PNG 文件名使用 UTC；菜单日期沿用已保存的本地/UTC 偏好，表示浏览器首次收到图像的时间，不代表台站发送时刻。

Radiofax 浮窗以图像为主体。紧凑工具栏集中接收页选择、新页、保存、缩放和跟随；接收状态行只描述实时接收器，页脚只描述正在查看的页面，避免将已完成历史页与当前失锁混淆。设置收纳捕获参数和校正控件，详情收纳时钟、信号测量、浏览器接收时间和内存使用。多段页才显示分段导航及整页/当前段保存选项。详情关闭时，留存受阻和缺少前段等警告仍可见；删除、清空位于“更多”中，并保留确认。

“跟随”是显示开关。关闭时固定当前页和存储段，保留滚动位置，解码仍继续；开启时切到最新页、最新段并滚到最新行。向上滚动也会暂停跟随；主动关闭后，即使当前已在底部也不会自动重新开启。

DSP 最多保留 20 MiB 原始 Gray8 行及同一批存储段的校正行（额外最多 20 MiB）。服务快照另有 20 MiB Gray8 预算，只移除完整旧段并保留原段号；晚订阅无法恢复页首时报告 `snapshot_prefix_missing`，不裁掉段首行后重新编号。仍保留的旧段继续参与时钟及手动校正。

WFM 保留立体声和 RDS。FM 分析单位为 Hz，固定 NFM ±5 kHz、WFM ±75 kHz 归一化先于自适应 AGC；关闭 AGC 不取消单位转换。立体声指示表示有导频，不保证节目左右声道内容不同。

共享 DSP 同时运行 AM 包络与载波恢复路径，`am_sync` 切换输出时平滑过渡。实时切换保留采集、滤波与重采样状态以及流时钟。AGC 前的载波与调制度分析、最终 PCM 电平和波形事件按 20 Hz 源样本时钟网格产生；浏览器显示这些结果，不从播放回调推算指标。同步检波开启与载波锁定是两个独立状态。

浏览器接收 AUD2 和 SDE2，不重复运行生产 IQ 解调器。每条播放链只有一个生产者。模式切换清空旧 PCM 并等待新起始边界；codec 实际率或声道变化也产生新音频边界。worklet ready 握手确定播放率，重采样适应设备与声卡时钟。溢出显式终止播放链。共享 crate 还支持已提交的浏览器 WASM 离线诊断产物；它们不替代原生服务构建。

AudioContext 创建和恢复错误只影响音频播放。浏览器忽略过期 worker 回调。本地解码器或初始化故障保持锁存，直到显式重试或出现健康的新流身份。接收器故障只有在 STATUS 明确报告健康且已启用频道获得新身份后才能清除。

UID 音频遇到传输关闭 1001/1006/1012 时清空播放缓冲，以 0.5–5 秒退避重建本地订阅；重新验证 AUD2 起始边界后恢复声音，不把网络缺口拼为连续 PCM，不提交接收配置。停用监听取消待重连；接收器、协议和慢消费者故障仍需明确恢复。UID 退役或服务代次变化时，先释放消费 worker，再释放结果缓存，迟到回调不能重建旧缓存。

## 前端状态与绘制

用户设置及后端确认的参数使用 `core/params.ts` 槽位管理：用户操作写入 desired，STATUS 确认实际值。纯客户端偏好以本地状态为准。测量结果存放在 `core/results.ts`，通过显式 setter 更新，不使用 desired/confirmed 语义。共享类型与注册表保持为叶子模块，由上层模块依赖。注册模块必须能从 `main.ts` 的导入链访问。

Decode 在窗格、频道或接收流变化时刷新所选 WFM 接收器。控制连接或设备断线时，先取消频谱手势并释放指针捕获，再重置接收状态；之后松开指针不会发送调谐命令。

### SDR 滤波与调谐控制

参数面板、数值输入和频谱叠层共用 `sdrDemod` 与 `sdrIfbw`，这两个参数槽仍是 desired/confirmed 值的唯一来源。自定义值保持显示，无精确匹配时不强行高亮预设。STATUS 确认值也会记录为该模式最近一次已确认值。切换模式时恢复该模式保存的已确认值；无有效保存值时使用模式默认值。普通调谐保留当前滤波器，Preset 按既有 SDR 偏好语义一并清除各模式记忆。

| 模式 | 默认值 (Hz) | 预设 (Hz) | 可编辑 |
|---|---:|---|---|
| AM/DSB | 6000 | 3000、4500、6000、9000、12000 | 是 |
| USB/LSB | 2400 | 1800、2400、2700、3000、6000 | 是 |
| CW | 500 | 100、200、500、1000、2000 | 是 |
| NFM | 12000 | 9000、12000、12500、15000、25000 | 是 |
| WFM | 180000 | 100000、150000、180000、200000、250000 | 是 |
| PM | 12000 | 6000、9000、12000、15000、25000 | 是 |
| FT8/SSTV/无线电传真 | 3000 | 界面固定 | 否 |
| DRM | 12000 | 界面选择/锁定 | 否 |
| DRM+ | 100000 | 界面固定 | 否 |

预设按钮使用紧凑的 k/M 后缀，悬停可查看完整 Hz 值。数值输入通过共享 units 控件保留完整的 Hz/kHz/MHz 选择；单位切换只改变表示方式，不改变底层 Hz 值。手动输入与虚拟键盘共用校验和提交路径。自定义值不受常用预设上限限制：AM 100 kHz、SSB 50 kHz、CW 10 kHz 等候选值在通过准入时均可使用。数值编辑器与后端均要求有限值不小于 50 Hz；USB/LSB 不小于 101 Hz，以防保护带退化。STATUS 为当前模式发布 `sdr.filter_limits:{mode,min_hz,max_hz}`：`min_hz` 为真实 DSP 下限（协议锁定或未知模式为 0 且 max 为 null），`max_hz` 是由当前采集中心/带宽、输入采样率、PFB tap、收听频率与 CW pitch 决定的整数采样上限，非 SDR、频道 1 停用或无可行范围时为 null。UI 检查这些动态界限，它们既不是硬件固定限制，也不是推荐预设范围；其他采样率、频道与成本准入检查仍可能拒绝范围内的值。

Filter 行提供数值输入、预设与“查看”。频谱通带的边缘抓手调整带宽，顶部频率滑块用于调谐，改变收听频率及 SSB/CW 的听感音调；它不修改 CW 侧音设置。

点击预设、按 Enter 或输入框失焦提交一次；Esc 取消草稿。边缘拖动先本地预览，松开时提交一次；pointercancel、窗口失焦和模式切换丢弃草稿。界面串行处理接收器编辑，保留一个在途请求和一个最新待处理候选。匹配 request ID 的确认推进队列；ERROR 或三秒未确认恢复已确认值。前端界限不替代后端准入。
调谐步进按解调模式分档：步进输入框和普通方向键用“普通”档，Shift+方向键用“粗”档，Ctrl+方向键用“细”档；两个按键档位的数值在内联设置面板中修改，输入值在按 Enter、变更或失焦时提交，Esc 或切换模式取消草稿。默认值对应各模式的信道规划——AM/DSB 为 1/5/0.1 kHz，USB/LSB 为 100/1000/10 Hz，CW 与 FT8 为 10/100/1 Hz，NFM/PM 为 12.5/100/1 kHz，WFM 为 100/1000/10 kHz，SSTV/DRM 为 1/10/0.1 kHz，DRM+ 为 10/100/1 kHz；未列出的模式读取一组保守的通用默认值。记忆值（不低于 1 Hz）按模式保存，与采集带宽完全解耦：调整带宽不影响步进阶梯，Preset 随其他 SDR 偏好一并清除三张档位表，并顺带移除已废弃的按带宽记忆步进键。

收听频率编辑同一时刻保留一条在途 `SET_SDR_CHANNEL` 调谐请求和最新排队目标。精确匹配 request ID 的确认独立于快照新旧顺序结束该请求，旧快照不能覆盖已确认状态。已取消或超时的请求身份不会恢复排队任务，但可携带版本严格递增的权威状态。ERROR 或三秒无回复会丢弃待确认意图并恢复已确认频率。有效新输入、取消、该请求的延迟确认或更新的权威恢复会清除调谐超时提示，不清除其他诊断。窗口失焦或标签页隐藏只丢弃排队的重复输入。切换解调模式、外部采集变化、采集手势、频段按钮、Preset 和断线取消在途调谐；匹配调谐确认引起的采集移动保留其有效队列。调谐快捷键在输入框、下拉框、文本域、可编辑区域、对话框、数字键盘和缩放概览框保留原生行为。聚焦按钮保留除调谐方向键外的按键；Shift 和 Ctrl 只修饰方向键。Alt、Meta 与 Ctrl+Shift 交给浏览器；输入法组合期间跳过，失焦或页面隐藏后停止重复。

主 SDR 监听频率及模式控件会明确重启已停用的 C1；重新提交相同频率也会恢复接收。仅采集带宽／平移命令保留信道启停状态。所有信道停止后，主面板重启通过既有 UID 扬声器归属恢复 C1 本地监听，保留本地增益、Pan 和总静音；健康接收状态确认后才开启播放。运行中调谐不覆盖手工监听选择，共享 PCM 增益编辑保持独立。

每次按下指针只确定一个手势归属。图区内的指针移动合并到单个动画帧，仅读取一次几何；悬停反馈、滤波把手、定位预览与光标读数只在可见内容变化时一次性重绘。顶部频率滑块用于调谐，开启缩放时同样可用；Ctrl 手势与已有标记菱形优先操作标记。带宽箭头位于透明通带外侧，鼠标靠近中线或可编辑边缘时显现，拖动时保持可见。开启缩放时，顶部箭头调整带宽，其余图区框选缩放；关闭缩放时，可编辑边缘也能调整带宽。窄通带保留分开的箭头命中区，不改变真实通带宽度；拖动按指针位移调整原截止频率。模式、采集、视窗、缩放变化，指针丢失、Esc、标签页隐藏或窗口失焦均取消手势而不提交。

普通 SDR 图区点击按“定位”选择目标：自由定位使用点击频率；频道定位使用 `锚点 + round((f − 锚点)/间距) × 间距`；信号定位选择可信载波。选择“频道”同时在原处展开间距（Hz，不小于 1 Hz，允许小数）和锚点（MHz，任意有限值），两行对齐且输入框等宽。没有独立的“网格”按钮。“步进”输入框旁的齿轮按钮单独展开调谐步进设置。

信号定位仅适用于 AM 和 CW。其他模式禁用该选项并以悬停提示说明，同时保留已存偏好。载波证据来自 Average 或 Max Hold 处理前的原生频谱帧。细频率轴上的捕获需要最近 350 ms 内至少三个连续可信帧，首尾至少相隔 120 ms。帧间隔超过 350 ms 或时间戳倒退会重置历史。分别计算峰值左右两侧相距 3–8 个频点的均值，峰值须比其中较高的均值至少高 8 dB；两侧肩部均须向外下降，并在距峰值 2–4 个频点处达到至少 4 dB 的降幅。AM 原生频点间距超过 1 kHz，或 CW 超过 min(250 Hz, IF 带宽/2) 时属于粗频率轴。粗频率轴从最新帧中选取最近的可信局部峰；若次近候选的距离差不足一个频点，则因目标不明确而拒绝捕获。

捕获半径为屏幕 40 像素，保持半径为 52 像素；细频率轴下，两者在 AM 均不超过 10 kHz，在 CW 均不超过 3 kHz，粗频率轴则采用 200 kHz 上限，同时保留像素限制。已选目标保持在原生频点中心，不做插值。细频率轴的支持峰值允许左右移动一个频点；粗频率轴的预览刷新与点击提交必须有最新帧中同一选定频点的证据。短暂掉信号时，从最后一次局部证据起最多保留预览 300 ms。点击要求当前帧仍支持同一载波、证据距今不足 300 ms，且源、配置和视图未变；缓存目标尚未超时不足以允许提交。CW 调谐频率为载波频率减去 max(100 Hz, 已确认侧音音调)。采集频率轴、解调模式或音调变化时清除载波证据。

只有有效的频道或信号目标显示预览线，且只在图区底部显示一个频率标签。自由定位不显示随指针移动的预览线，信号定位没有常驻提示行。点击目标在 pointerdown 时冻结，提交前再次校验。视图、模式、音调、IF 带宽、频道设置或收听频率变化会使目标失效。信号目标失效时回退到点击频率，并显示简短提示。

图区上方收听频率标签的绘制与命中检测共用几何；拖动保留指针偏移，在视窗和射频范围内预览，松开提交。拖动标签、图区调谐或滤波边缘时，瀑布同步显示通带与频率线；松开或取消后恢复干净的历史像素，冻结时也一样。

绿色通带在深浅主题均使用24%不透明度，两侧细实线仅在拖动时按真实滤波边界显示。

SDR 电平读数固定为 10ch，文字居中；IQ 电平暂不可用时保留 `--- dBFS`。静噪读数固定为 9ch，开启时保留 dBm 单位，设为 −160 dBm 或更低时显示“关闭”。AGC 位于音量行静音按钮左侧。英文 Mute On 表示已静音、Mute Off 表示正在播放；中文分别显示“静音 开”和“静音 关”。这些控件只改变监听，不停止协议解码。

刷新或接入已运行的 SDR 会话时，本地播放器应用一次已保存的音频偏好。自动播放挂起期间，画布状态区显示恢复提示，首次交互后自动消失。PCM 订阅等待 AudioContext 运行后才启动，避免自动播放被挂起时积压溢出。普通点击或按键会重试浏览器的播放许可，无须切换静音；已保存的静音仍保持关闭播放。接收器故障继续明确报告。

滤波手势只改变滤波器。“查看通带”保存显示窗口和缩放开关状态，并高亮按钮；再次按下恢复两者。手动改变视窗、改变采集、切换模式或重置会丢弃保存状态。视图使用原始频点，缩放不提高频谱分辨率。

后端返回原生频率网格。前端为标记和导出保留以 Hz 表示的原始频率，显示时采用保峰重采样，将未覆盖的边界频点绘制为缺口。对外呈现的 SDR 窗口裁剪到设备 RF 范围内，采集仍保留请求的中心与带宽；被裁剪的中点不会改变平移目标或请求调谐。频点间距不等于 RBW。本地缩放只改变可见窗口，不重新调谐或改变接收时钟。同宽度的频率轴平移让概览中的放大矩形保持固定，频谱与收听标记从框下滑过。主图按放大后的每像素频率跨度移动，确认后视窗随采集平移并在边缘钳位。频率轴手势拥有视窗位置，即使后端为适配新通带而调整监听频率，确认和周期 STATUS 也不得将视窗重新居中；新轴手势取消等待采集帧的自动跟随。滚轮改变采集带宽、切换模式、Preset 或用户关闭缩放会退出放大；量化后的采集无法容纳视窗时也返回完整采集视图。开启缩放时，跳转窄条换成与分组按钮同宽的缩放滑块，并在滑块条上显示一个切换按钮，可在分组按钮与滑块之间来回切换；关闭缩放后该按钮消失，并回到分组按钮。密度和瀑布历史均有容量上限。参数槽位在高频循环外一次性读取。

按下 SWP、RTA 或 SDR 频率轴时均保留当前放大窗口，不切回完整采集带宽。手势在按下时保存该窗口及每像素对应的频率跨度；频谱、频率刻度、标记与瀑布共同预览平移后的放大窗口，采集请求仍保持完整采集带宽。按住期间到来的新帧不会改变拖动比例，松手及紧接的下一次拖动也会保留预览，直到采集窗口追上请求。概览窗在拖动中使用目标采集窗口和显示窗口：频谱与 SDR 监听标记立即从固定的放大框下滑过，频率范围也实时更新，无须等待松手；取消手势后恢复已确认的范围。预览仅按原始 RF 位置显示已有样本，新请求的频率区域在实际采集前保持为空。

SWP 调谐后，原生扫频网格的两端可能重新对齐到相邻频点。仅在同带宽的频率轴平移尚待完成、且新 FREQ 端点与目标相差不超过两个边缘频点间隔时，保留并平移放大窗口；预览也只在收到新网格后按该频点精度结束。其他采集跨度编辑仍会清除局部放大。

在放大模式下，中心频率设置保留明确居中的语义。监听频率输入和步进调谐收到确认后，仅当监听频点或通带超出当前视窗时，以最小位移滑动放大框，使两者进入视图；已完整可见则保持视窗。跟随使用确认的解调模式、带宽和 CW pitch，并将目标裁剪到采集边界；通带宽于视窗时，监听频点已可见则保持原位，否则将频点居中。跟随保持缩放倍率，不修改采集中心或监听频率，采集不足时以采集边界为限。真正的采集重定位仍等待匹配的新帧；拒绝、过期回报及后续手动视图操作不能触发旧定位。图区点击和顶部频率滑块调谐保持所指的频率轴。拖动预览尚未结束时，点击定位、定位预览和滤波抓手均使用与迹线及刻度一致的预览坐标。

To Center 明确将放大框定位到监听频率，即使采集中心与监听频率原本相同也执行；旧的轴拖动预览先取消。自动跟随、中心定位及概览空白处点击以约 240 ms 的渐缓滑动移动同一个频率视窗，主频谱、刻度、通带、瀑布和概览框同步。新的定位从当前可见位置接续；直接拖动、重置或采集变化中止旧动画。减少动态效果偏好启用时立即定位。

SDR 命令确认与频谱元数据独立发布：确认中的中心频率已更新时，`sdr.actual.start/stop` 仍可能属于旧采集。定位先核对元数据的中心和 decimate；缺少身份字段时核对边界与已确认中心是否一致。过期边界不能作为新定位的采集目标；此时按已确认中心和带宽推导目标，等待匹配的新频谱帧再滑动，后续旧元数据回报不会再次平移或取消定位。

SDR 概览窗以绿色顶部小三角和竖向虚线标示当前监听频率，颜色沿用主图监听标记。监听点在放大矩形之外仍保持可见，拖动主图监听标记时同步预览；监听频率超出采集窗口时隐藏。SWP 和 RTA 概览窗不显示接收器标记。

频谱 CSS 盒决定画布几何，位图尺寸通过 ResizeObserver 跟随。启用瀑布时，绘制路径和 STATUS 驱动的测量 UI 刷新均保持标记表隐藏。STATUS 不能临时恢复该表，否则频谱会缩小并因位图尺寸变化而清空，直到下一次绘制再次隐藏表格。

SWP、常规 RTA 与 SDR 频谱更新以 30 fps 为目标，使用一个以上次帧绘制时刻为基准的尾随定时器。SWP 对每个有效扫描执行迹线、瀑布和触发处理；RTA 与 SDR 处理最新待处理的常规帧，包括突发到达的最后一帧。首帧、频率轴变化及已布防的 RTA 捕获仍立即处理和绘制。模式切换、采集变化、触发重置和断线会取消待处理工作；延后的 SDR 帧还会核对采集设置和配置版本。UI 重绘请求保持同步。编码后的显示数据在订阅者之间共享不可变字节，传输数据和原生频率分辨率保持不变。

轴拖动本地预览，手势稳定后提交。手动 Ref 拥有独立本地窗口（-200 至 +100 dBm 加 Offset），硬件请求单独限幅至 -160 至 +40 dBm；原始请求确认保留所选显示窗口。增益回读来自当前模式成功配置后的 SDK 实际值；无法获取时保持 null。前置放大 `0` 表示 Auto、`1` 表示 Off，不能据此宣称物理放大器已开启。RTA 捕获依据随 RTA2 帧传输的设备触发元数据；SDR 继续使用 RTAF，旧格式解码仅供兼容。收到帧或等待一段时间都不能证明捕获完成。SWP 在前端根据相邻扫描判断电平交叉。参数、Auto、迹线、测量与触发约定见 [MODE_STATE_FLOW](MODE_STATE_FLOW.md)。

SDR 频率轴平移同一时刻只保留一条在途 `SET_SDR` 请求，并仅保留最新未发送窗口。只有匹配 request ID 的回复确认该次平移；周期 STATUS 和旧确认不能改写更新的目标或仍按住的指针起点。请求被拒绝时丢弃未发送窗口，重置会取消待确认的手势状态。频率越界错误包含通道编号、被拒绝的频率和允许范围。

## 质量边界与验证

后端三个槽不表示 UI 提供三路接收器，也不表示无限监听或录制。FT8 在支持的搜索窗内处理标准类型 1/2；SSTV 不解码图像后的 FSK 呼号。RDS 文本质量和短段/循环 DRM codec 播放仍有约束。[KNOWN_ISSUES](KNOWN_ISSUES.md) 记录当前限制及 SDK 边界。

浏览器 SWP/RTA 的 30 fps 调度目标取决于输入帧率与绘制开销，不代表已测硬件吞吐，也不改变后端采集时序。这些描述归纳实现；维护文档不构成重新验收硬件。

可复现入口包括：`make wasm-test` 验证共享 DSP，`make ci` 执行本地无硬件门禁，`make e2e-fake` 验证原生 fixture UI。`tools/bench/sdr_pipeline_check.py` 和 `sdr_pipeline_controls.py` 检查 live IQv2 连续性及控制；原生 `websad --sdr-pipeline-bench` 覆盖流水线。命令选项及依赖见 [tools](../../tools/README.md)。硬件验收必须核对内容、硬件时间戳、队列/失败增量和排空后的样本守恒；假源吞吐或短窗口不能证明持续 RF 运行。浏览器检查与安静的硬件性能窗口分开，见 [DEVELOPMENT](DEVELOPMENT.md)。
